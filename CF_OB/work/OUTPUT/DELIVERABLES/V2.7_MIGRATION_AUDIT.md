## 2. Runtime coupling that blocks deletion

From `V2.7_BASELINE_AUDIT.md` §6 (64 legacy-ref hits). The blocking sheet is **POSTING**:

| Referrer module | Direction | Evidence |
|---|---|---|
| `modCF_Posting` | **WRITE** | sets `wsRaw.Name="POSTING"`, drives MIGO 311 |
| `ModuleSAP` | READ | `Worksheets("POSTING")` ×2 |

Deleting POSTING now breaks the posting write flow. This is the GATE.

## 3. POSTING-removal protocol (8 steps — NOT yet executed)

1. Build `SourceStockRepository` (in-memory) + `tblSourceStock` backing store, shaped from live POSTING columns.
2. Migrate the **reader** sites (`ModuleSAP`, `modSAPReadOnlyProbe`) to the repository.
3. Migrate the **writer** (`modCF_Posting`) to write the repository instead of `wsRaw.Name="POSTING"`.
4. Compile full project (Application.Run self-test) → must be clean.
5. Run the full offline regression suite → must stay green.
6. Static grep: confirm **zero** `Worksheets("POSTING")` / `Sheets("POSTING")` runtime references remain.
7. Only then: VeryHidden POSTING for one release as a safety soak (reversible).
8. Finally: delete POSTING + fold remaining sheets to the 5-sheet model.

**Steps 1 and depends-on-live-data:** step 1 needs the real POSTING column shape,
which in turn needs live POSTING data → `BLOCKED_EXTERNAL`. Steps 2–8 cannot start
until step 1 is done. Therefore the entire destructive migration is GATED.

## 4. What IS safe offline (reversible) — and why it was still not applied

- VeryHidden-ing sheets is reversible and non-destructive. It was **not** applied,
  to honor the user's ordering principle: *do not change workbook structure before
  the Allocation Engine is proven, or later you can't tell whether a bug came from
  new logic or from sheet migration.* Since live proof (Tier F) is still outstanding,
  changing structure now would muddy any future live diagnosis.

## 5. Migration integrity checks (to run when un-gated)

- Plan parity: PLAN lock cells + fingerprints survive the fold.
- Live-proven branches unchanged: no proven SAP path altered by the fold.
- Bug-fixed state preserved: net-zero allocation still yields the member Create.
