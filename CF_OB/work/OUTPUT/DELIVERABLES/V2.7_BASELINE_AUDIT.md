## 6. Legacy-sheet reference map (64 hits) — migration risk surface

The heaviest runtime coupling (must be resolved before any sheet deletion):

| Module | Sheet | Hits | Note |
|---|---|---|---|
| modCodexWTRework | WH_ACTUAL | 34 | core executor |
| modCodexWTRework | PLAN | 10 | plan read/write |
| modCodexWTRework | INPUT | 5 | OB list |
| modSAPRunGuard | SAP_MAP | 6 | fingerprint map |
| modCF_Posting | WH_ACTUAL / POSTING / INPUT | 3 / 1 / 2 | **POSTING writer (MIGO)** |
| modSAPReadOnlyProbe | POSTING | 2 | POSTING reader |
| ModuleSAP | POSTING / ORDER_QUERY / SAP_MAP | 2 / 2 / 1 | POSTING reader |

**POSTING is referenced by 3 runtime modules** (`modCF_Posting` writes it via MIGO;
`ModuleSAP` + `modSAPReadOnlyProbe` read it). This is why the 20→5 migration's
destructive half is GATED — see `V2.7_MIGRATION_AUDIT.md`.
