# V2.8 USER-REPORTED ISSUES (2026-08-21)

## Source
User feedback trước khi tiếp tục Phase 3 structural work.

## Issues reported

### 1. ❌ GROUP CANCEL VẪN BỊ CHIA NHIỀU LẦN
**Mô tả:**
- 1 OB cancel 4-5 vị trí → tool chia thành 2-3 lần cancel (không cancel group 1 lượt)
- Example: 1 OB có 7 dòng, cần cancel 4 WT + tăng 2 WT + giảm 1 WT → vẫn bị chia ra nhiều lần cancel riêng lẻ

**Root cause (preliminary):**
- Suspect: `CFX_GroupKey` logic hoặc cancel scheduler không group đúng
- Hiện tại group key = `QtyGroupId` frozen trong PLAN (nếu có), else fallback `"QG|" & DocNo & "|" & Item & "|" & PlanID`
- Cancel queue có thể đang build per-member thay vì per-group aggregate

**Impact:**
- Slow (nhiều lần vào SAP)
- Không tối ưu batch operation

**Related code:**
- `modCFX_Planner.bas` CFX_GroupKey (line 195-200)
- `modCFX_Scheduler.bas` cancel queue builder (chưa đọc)
- `modCodexWTRework.bas` CWR batch cancel logic

**Cần kiểm tra:**
1. CFX_GroupKey có đang build stable group across all cancel members không?
2. Cancel scheduler có aggregate cancel members into 1 batch không?
3. Log V2.71 history: tìm cancel events, check xem ActionKey có chứa group markers không

4. User có thấy blocked feedback trong worklist không? (Phase 1b chưa ship)

### 3. ❌ THÔNG BÁO CHƯA ĐẦY ĐỦ VÀ KHÔNG PHẢI TIẾNG VIỆT

**Cần kiểm tra:**

3. V2.71 history: tìm CHANGE_BIN events, check frequency

### 5. ❌ LUỒNG CHẠY CHƯA TUẦN TỰ (NON-SEQUENTIAL FLOW)
**Mô tả:**
- Tool không chạy theo thứ tự tối ưu
- Không "tối giản luồng chạy"
- Không "tối ưu cho việc trả hệ thống" (release system resources faster?)

**Root cause (preliminary):**
- Unclear: user muốn sequential theo nghĩa gì?
  - Sequential by document? (finish Doc A completely before Doc B)
  - Sequential by stage? (finish all cancels before all creates)
  - Sequential by group? (finish group 1 completely before group 2)
- Current design: group-parallel (nhiều groups chạy interleaved để exploit SAP session reuse)

**Impact:**
- User perception: tool "nhảy lung tung"
- Possible: harder to debug/audit

**Cần làm rõ:**
1. User muốn sequential mode nào?
2. Trade-off: sequential → slower but simpler to follow; parallel → faster but complex

---

### 6. ❌ ĐIỀN SỐ LƯỢNG NHẢY NHANH, MÁY YẾU + OB NHIỀU DÒNG → MAP THIẾU
**Mô tả:**
- Qty-change step: tool scroll nhanh qua các dòng
- Máy yếu + OB nhiều dòng → "từ vài ô phía dưới chưa kịp load" → map thiếu
- Suspect: SAP grid lazy-load (rows not yet rendered) → .getText() returns blank

**Root cause (preliminary):**
- Confirmed SAP GUI Scripting issue: grid lazy-loads off-screen rows
- Tool reads grid too fast after scroll → some cells not yet populated
- V2.8 Bug B fix only addressed CREATE_CONTEXT reuse, not grid lazy-load

**Impact:**
- Map incomplete → tool misses some members → bỏ sót mã (relates to Issue #2)

**Related code:**
- Grid read logic in CHECK phase (modCF_CheckPlanner? modSAPReadOnlyProbe?)
- Need explicit wait after scroll before .getText()

**Fix required:**
- Add scroll-wait-read pattern:
  1. Scroll to row range
  2. Wait 200-500ms (grid render time)
  3. Read .getText()
- Or: use SAP table.getAbsoluteRow() API (slower but guaranteed)

**Cần làm rõ:**

- Example: group by Material across documents? Group by Bin?
