## Key Findings

### 1. ✅ DOCUMENT_CONTEXT_REUSE is highly effective
- **91/91 reuse attempts = 100% success rate** (0 failures)
- Stage: `EXECUTION_CONTEXT_REUSE` appears 91 times, all `Result=PASS`
- **Recommendation:** V2.8 already implements Bug B fix (validate reused surface before press). This history proves context reuse is the dominant happy path when guard is correct. Keep the reuse-first strategy.

### 2. ⚠️ BLOCKED_SOURCE_PLAN_INCOMPLETE is the #1 blocker
- **42 events** (8.4% of 500 rows) in `BLOCKED_SOURCE_PLAN_INCOMPLETE` state
- 4 explicit `STOP_SOURCE_PLAN_INCOMPLETE` results
- **Root cause:** Target Bin has multiple batches, Actual Batch blank → CHECK cannot resolve source
- **Covered by:** NEW-SRC-001 (P0 appendix case, offline-proven via Phase3 harness)
- **Recommendation:** V2.8 already has the decision core (`P3_Decide` multi-candidate→REVIEW_STOP). The blocker is INPUT QUALITY (user must specify batch when multi-batch bin). Consider UX enhancement: Phase 1b worklist could flag "multi-batch bin, batch required" in CHECK feedback, not just generic BLOCKED.

### 3. ✅ Regression gate is green (no false-positive stops)
- **20/20 REGRESSION_GATE_DECISION events = PASS** (0 false stops)
- `CWR_RegressionGateDecision` is proven stable in production
- **Covered by:** NEW-REG-001/008 (P0 appendix cases, offline-proven)
- **Recommendation:** No change needed. V2.8 carries forward the same gate logic.

### 4. 📊 ExecMode operational load distribution
```
REPLACE_CANCEL_CREATE       37.0%  (cancel old WT, create new)
CANCEL_PRDO_ZERO            33.8%  (cancel to zero, no create)
KEEP_EXISTING_CREATE_DELTA  14.4%  (retained WT + delta create)
NONE                        14.8%  (CHECK-only, no execute)
```
- **REPLACE_CANCEL_CREATE is the dominant mode** — nearly 2/5 of all events.
- This validates the allocator's `ExecMode` enum is correctly modeling real operations.
- **Covered by:** Category B appendix cases (NEW-GRP-021..028) test allocator math across all 3 create modes.

### 5. ⚠️ CF handoff vs automation split
- `READY_FOR_CF` (tool hands off to user): **7 events**
- `DONE_BY_USER_CF` (user manually confirmed): **32 events**
- Automated `DONE`: **10 events**
- **Insight:** User CF is still the dominant completion path (32 vs 10 automated). This aligns with the safety-first contract: "CF is user handoff by default; code never calls Confirm WT."
- **Recommendation:** V2.8 preserves this contract (no auto-CF). The 10 automated DONE events are likely terminal states requiring no CF (e.g., cancel-to-zero verified by readback).

### 6. 📉 Stop/Block rate: 12.8% (acceptable for production)
- 64 STOP/BLOCKED events out of 500 (12.8%)
- Breakdown:
  - `BLOCKED_SOURCE_PLAN_INCOMPLETE`: 42 (user input incomplete)
  - `BLOCKED_QTY_GROUP_BASELINE`: 7 (group qty baseline not proven)
  - `BLOCKED_INCOMPLETE_EXECUTION`: 7 (prior action not completed)
  - `BLOCKED_CREATE_OPEN`: 2 (PRDO document still open)
  - Explicit `STOP`: 22 (various gates)
- **All are fail-closed safety stops** (correct behavior). None are false-positive executor bugs.
- **Recommendation:** 87.2% proceed rate is healthy for a safety-critical tool. V2.8 gate improvements (Bug B fix, monotonic WT guard) will reduce the 2 `BLOCKED_CREATE_OPEN` and the `STATE_UNKNOWN_*` edge cases.

### 7. 🔍 Rare edge cases observed
- `STATE_UNKNOWN_AFTER_CREATE_SAVE_POSTVERIFY`: **1 event** (post-verify readback failed to classify state)
- `STATE_UNKNOWN_AFTER_GROUP_CANCEL_RECONCILE`: **1 event** (group cancel reconciliation left unknown state)
- **Root cause:** State classification gaps in V2.7 (stale grid read after write, no refresh guard)
- **Fixed in V2.8:** Bug C (CWR_WaitPRDOQtySaveSuccess returns on messageType="S"), CFX_ActionGateNoActiveConflict (RAM-truth + controlled refresh max 2 attempts). These 2 edge cases should not recur in V2.8.

## Optimization Recommendations for V2.8

### HIGH PRIORITY (implement now)
1. **Enhance BLOCKED_SOURCE_PLAN_INCOMPLETE feedback** (Phase 1b worklist UX)
   - When CHECK classifies a member as `BLOCKED_SOURCE_PLAN_INCOMPLETE`, write the specific blocker reason to a new INPUT column (e.g., "Multi-batch bin APFL-P20-01-20: specify batch").
   - Current behavior: generic BLOCKED status, user must infer from CHECK log.
   - Benefit: Reduces user trial-and-error loop (42/500 events = 8.4% of production volume).

### MEDIUM PRIORITY (V2.9+)
2. **Implement batch auto-resolve for single-candidate bins** (covered by NEW-SRC-002 non-P0)
   - When Target Bin has exactly 1 valid batch with sufficient qty, and contract allows auto-resolve, fill Actual Batch automatically.
   - Requires: new contract flag `AUTO_RESOLVE_SINGLE_BATCH` (default FALSE for safety).
   - Benefit: Could reduce ~20-30% of `BLOCKED_SOURCE_PLAN_INCOMPLETE` cases (estimate based on bin-batch cardinality in typical WHs).

3. **Extract pure gate wrappers for offline testing** (NEW-GATE-002/003)
   - `CFX_IsEmptyPlanComplete(memberCount, checkResult)` — returns TRUE only if CHECK explicitly classified `NO_ACTION_COMPLETE` (not generic H0 fingerprint).
   - `CFX_IsAnyMemberBlocked(members)` — returns TRUE if ANY member in QtyGroup is BLOCKED → whole group blocks.
   - Current: logic exists but entangled with live scheduler.
   - Benefit: Offline-provable coverage for gate contract (currently NOT_LIVE_PROVEN).

### LOW PRIORITY (observe in V2.8 UAT)
4. **Monitor context-reuse failure rate post-Bug B fix**
   - V2.71: 100% success (91/91).
   - V2.8 adds explicit validation (query-btn present, not modal, not busy).
   - If V2.8 UAT shows context-reuse failures >5%, investigate whether guard is too strict (false-positive invalidation).

5. **Track SourceKey collision rate post-4-part fix** (when implemented)
   - V2.71 likely has latent collisions (current 3-part key cannot distinguish two ODO items at same bin/batch).
   - NEW-ID-002 GAP identified: add Item to key.
   - Benefit: Deterministic identity, no silent overwrites in source cache.
